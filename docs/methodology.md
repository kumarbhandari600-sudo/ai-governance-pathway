# Methodology

This project uses **Design Science Research (DSR)** (Hevner, 2007; Hevner & Chatterjee, 2010).

## Three cycles

- **Relevance Cycle:** Engage with the gap and existing evidence.
- **Design Cycle:** Iterate on the pathway across four sprints, one for each checkpoint.
- **Rigor Cycle:** Draw on NIST AI RMF, AI Ethics Principles, and the ACS Code.

## Why DSR?

DSR fits because the primary output is a practical artefact — a governance pathway — and the evaluation is against the problem it is designed to solve, not against feature delivery. Agile would suit a software product. Mixed methods would require primary data collection.

## Evaluation

Two external reviewers: one IT project manager, one academic mentor. Both must rate each checkpoint as actionable.
